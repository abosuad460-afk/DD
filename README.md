# ألفا ميد — نظام مخزون الأدوية الذكي

منصة عربية متكاملة لإدارة مخزون الأدوية والتنبؤ المبكر بالنقص، صُممت للصيدليات والمستودعات والمنشآت الصحية لمساعدتها على اتخاذ قرارات أسرع وأكثر دقة، وضمان استمرارية توفر الأدوية للمرضى.

يدعم النظام اتجاه الكتابة من اليمين إلى اليسار، ويستخدم **خط ثمانية** وهوية بصرية حديثة، مع واجهات متجاوبة تعمل على أجهزة الكمبيوتر والجوال.

## المزايا الرئيسية

- لوحة قيادة تنفيذية لعرض صحة المخزون والمؤشرات المهمة.
- متابعة الأدوية والكميات وحدود إعادة الطلب والمخزون الآمن.
- تصنيف الأدوية إلى حيوية وأساسية ومرغوبة.
- توقع تاريخ نفاد كل دواء بناءً على معدل الاستهلاك.
- تنبيهات مبكرة للأدوية منخفضة أو حرجة المخزون.
- إنشاء طلبات التوريد ومتابعة مراحلها حتى الاستلام.
- اقتراح بدائل علاجية تتطلب اعتمادًا صريحًا من الصيدلي.
- تحليل تأثير الظروف الجوية على سلاسل الإمداد.
- مركز تقارير تنفيذي مع الرسوم البيانية والطباعة وتصدير CSV.
- تسجيل دخول وإنشاء حسابات آمنة باستخدام Clerk.
- استقبال طلبات انضمام المستفيدين ومتابعة حالتها.
- قبول أو رفض المستفيدين وتحديد أدوارهم من لوحة الإدارة.
- إدارة الجهات والمنشآت الشريكة وبيانات التواصل وحالة التشغيل.

## الأدوار والصلاحيات

يدعم النظام أربعة أدوار:

| الدور | أبرز الصلاحيات |
|---|---|
| مدير النظام | إدارة المستفيدين والشركاء والمخزون والتوريد والتقارير |
| الصيدلي | إدارة المخزون، مراجعة البدائل العلاجية، وعرض التقارير |
| مسؤول التوريد | إنشاء طلبات التوريد ومتابعتها وعرض التقارير |
| المستفيد | متابعة المخزون المسموح وطلب الانضمام للمنصة |

يتم التحقق من الصلاحيات في واجهة المستخدم وفي خدمة API، ولا يعتمد النظام على إخفاء عناصر الواجهة فقط.

## التقنيات المستخدمة

### الواجهة

- React 19
- TypeScript
- Vite
- Tailwind CSS
- Wouter
- TanStack Query
- React Hook Form وZod
- Recharts

```text

├── screenshots/
└── pnpm-workspace.yaml
```

## التشغيل محليًا

### المتطلبات

- Node.js
- pnpm
- مفاتيح Clerk
- قاعدة PostgreSQL عند تشغيل الخصائص المعتمدة على التخزين الدائم

### تثبيت الاعتمادات

```bash
pnpm install
```

### متغيرات البيئة

أضف المتغيرات التالية إلى Secrets أو ملف البيئة المحلي. لا تحفظ قيمها داخل Git:

```env
CLERK_SECRET_KEY=
CLERK_PUBLISHABLE_KEY=
VITE_CLERK_PUBLISHABLE_KEY=
SESSION_SECRET=
DATABASE_URL=
```

### تشغيل خدمة API

```bash
pnpm --filter @workspace/api-server run dev
```

### تشغيل تطبيق الويب

```bash
pnpm --filter @workspace/med-stock-intelligence run dev
```

## أوامر التطوير

```bash
# فحص TypeScript في كامل المشروع
pnpm run typecheck

# بناء المشروع
pnpm run build

# إعادة توليد React Query hooks ومخططات Zod بعد تعديل OpenAPI
pnpm --filter @workspace/api-spec run codegen

# تطبيق مخطط قاعدة البيانات في بيئة التطوير
pnpm --filter @workspace/db run push
```

> عند تعديل `lib/api-spec/openapi.yaml` يجب تشغيل أمر `codegen` قبل استخدام الأنواع أو Hooks الجديدة.

## مبادئ مهمة

- البدائل العلاجية لا تُعتمد تلقائيًا، بل تحتاج قرارًا صريحًا من الصيدلي.
- صفحات النظام وواجهات البيانات محمية بجلسات Clerk.
- واجهة الويب تعتمد على Cookies الآمنة ولا تخزن رموز الدخول يدويًا.
- لا يجب رفع الأسرار أو مفاتيح الخدمات إلى مستودع GitHub.
- البيانات التجريبية الموجودة هدفها عرض تجربة المنتج ويمكن استبدالها ببيانات تشغيلية فعلية.
